我给了它一段 20 秒的视频，让它改成竖屏。

它没急着下剪刀，先报了一串数：原片 1280×720、30 帧、单声道。

裁完，它又提醒我：这一刀只留下 32% 的画面。

最后交出一张 13 项的检查单：0 项失败，1 条提醒。

我说的「它」，不是某个剪辑软件，是给 AI 用的一个工具包，叫 ffmpeg-skill。

会写代码的 AI，其实一直在猜

FFmpeg 是视频圈的老牌免费工具，转码、切片的底层几乎都靠它，但它的命令行很吓人。

项目作者把病因写得很直白：一个「懂 FFmpeg」的 AI，其实还是靠猜。

猜帧率，猜错编码，把本来复制一下就能完成的活儿重新压一遍，最后连文件都不打开，就说「完成」。

我自己也见过这种「好了」：听着像干完了，打开一看，尺寸不对，声音没了。

它做的是另一件事：把「剪视频」拆成一个个可以量出数字的动作。

官方首页那张图：一次剪辑的结果先被量成 59.98 秒、1080×1920、30fps、-14.0 LUFS，才写上 verified（来源：项目仓库 brand/og.png）

42 把带刻度的工具

ffmpeg-skill 不是一个带按钮的软件。它是给 Claude Code、Cursor、Codex 这类编程助手用的一套技能：42 个工具，配一个 MCP 服务。

MCP 你可以理解成一个通用插座，AI 客户端插上就能调用这些工具。

能干的活不玄乎：切段、拼接、去静音、横屏改竖屏、烧字幕、卡拉 OK 式逐字高亮、响度统一、调色、绿幕，还有给 TikTok、Reels、Shorts 一键出片。

关键在三个规矩。

先量后剪：每个活开始前，先用 probe 把时长、帧率、分辨率、音轨量一遍，不看文件名猜。

只给有名字的参数：比如「改成 9:16、裁切」，它自己去拼 FFmpeg 命令，不让 AI 随手写一串 shell。

干完复检：输出文件要再量一遍；画面变过，还要抽帧拼成一张联系表，让 AI 自己看一眼。

全程在本机跑。不上传素材，不要 API key，除了 FFmpeg 和 Python 标准库，没有别的依赖。

官方示例：一场演讲和幻灯片并排、切片、加字幕，全由一条条指令完成（素材为 Google Veo 生成，官方标注）

我拿一段 20 秒的测试片试了

本机 Windows 10，ffmpeg 8.0.1。我用一段合成的 20 秒测试片跑了一遍：先 probe，再裁成 9:16，套 Reels 规格，烧三条中文字幕，最后 check。

几个真实数字：

  • 原片 1280×720，裁完 406×720；工具当场提醒，这一刀只留下 32% 的画面，还给了「加黑边」和「模糊填充」两个替代。
  • 成片 1080×1920、30 帧；响度从 -21.8 LUFS 自动拉到 -14.1 LUFS，真峰值 -4.7 dBTP。
  • 交付检查 13 项，0 失败，1 条提醒：没有字幕轨。字幕烧进画面不算字幕轨，它照样提醒。
  • 中文字幕能直接烧，字体自动选了微软雅黑；字号从 24 缩到 20，只为让两行放得下。

本机实测的验收单：13 项检查、0 失败、1 条提醒（来源：本机运行 probe / fit / export / check 的实际输出，2026-11-24）

最让我服气的是那张「没量到」的清单。

它会老实写：画面里是谁、裁切有没有切到人、字幕好不好看，这些我没量，你自己看。

这比一句「已完成」可信。

不满意，写句人话就行

剪完会生成一个本地网页：左边是素材和每一步的检查，中间是竖屏成片加平台安全区，右边是时间线。

你按下某个镜头或某句字幕的编号，写上「这里再往左一点」「这句太长了」，它会把这句意见变成一条给 AI 的指令，复制回去就能改。

页面有中文，素材不出本机。

官方评审页：素材、每一步的检查、竖屏成片和操作线都在一页上，按编号写意见会生成给 agent 的指令（来源：项目仓库 site/media/review_en.png，界面支持中文）

本机实测：左边是裁好的竖屏，右边是烧上中文字幕之后；字幕自动抬到 Reels 的安全区（合成测试画面）

三盆冷水

第一盆，它是「手」，不是「脑」。它不替你决定剪哪段、不找爆点、不写字幕文案。你得先知道要什么，或者前面还有一个会判断的 AI。

第二盆，Windows 还没被官方跑全。作者在 README 里自己写：完整的真实设备素材只在 Linux 和 macOS 跑过，Windows 还没跑完，issue #143 挂着。我这次能跑通，只能说明这条 20 秒的路通了，不等于你那些手机拍的素材都没坑。

第三盆，版本密得吓人。仓库到今天一共 251 个发行版，11 月 22 日一天发了 8 个；42 个工具里，只有 12 个标了稳定，其余 30 个是 beta。还有一条实务提醒：一小时的长片整条重编码会撞上默认 30 分钟的超时，官方实测 1802 秒被杀，得手动放宽。

作者还写了篇论文讲这套「每一步都验证」的方法，论文里给自己的项目打分：只算部分合格。

这种自己拆自己台的态度，我反而愿意信。

我的看法

它今天 10,254 星，9 月 3 日建的仓，两个多月。

比星数更值得记的是这个方向：AI 干活正在从「会生成」走到「敢验证」。

以后你判断一个 AI 靠不靠谱，可以少听它说「好了」，多问一句：数字呢？
