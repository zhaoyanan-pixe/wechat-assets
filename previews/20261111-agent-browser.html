今天早上八点，我在这台电脑上敲了四条命令：打开 example.com、让它把页面读一遍、点它给的「第 451 号」、再看现在停在哪。

页面已经跳到另一个网站了。全程没截图，没算鼠标坐标，我也没碰鼠标。

这东西叫 agent-browser，Vercel Labs 出的开源命令行工具，Rust 写的，Apache-2.0 协议。今早八点零三分我查了一眼：约 4.9 万颗星、3,400 多个 fork（别人复制出去自己改的版本数），上个月在 npm 上被下载 853 万次。

它不给 AI 看图，给的是编号

平常我们说「让 AI 上网」，多数产品走截图路线：拍张图，让模型猜按钮在哪，再按坐标点。听着聪明，其实很脆，页面挪一像素就可能点歪。

agent-browser 换了条路：它把网页压成一份纯文本清单，清单里每个能点的东西后面挂一个编号，长这样：- link "Learn more" [ref=e451]。

本机实截：GitHub 仓库页上每个可点元素都带一个编号（agent-browser screenshot --annotate）

AI 只需要说「点 e451」，工具去点；点完再读一遍页面，确认事情有没有成。浏览器一直开着，每条命令只是终端里的一句话。

这份清单有正经名字，叫可访问性树（accessibility tree）。浏览器本来就给读屏软件准备了一份「这页有什么、哪个能点」的说明书，它直接拿来喂给 AI：不用猜像素，也不用把整页代码塞进去烧钱。

还有个细节值得说：浏览器不关，后台有个常驻的小进程（daemon）通过 Chrome 的调试接口控制它，闲置一小时没命令才自己退出。所以你在终端里看到的是一行行结果，而不是一个挂着的窗口。

我本机跑了一遍，踩了个小坑

装它用 npm，一条命令，20 秒装完，版本 0.42.0。然后四步，一轮不到十秒。

本机实测记录：打开 → 读清单 → 点编号 → 看结果（Windows，2026-11-11 08:07）

顺手发现一个坑：README 示例里的编号写的是 e1，我这儿跑出来是 e451。我照着 README 敲 click @e1，直接报 Unknown ref: e1。

不是 bug，是我一开始理解错了：据我观察，编号只往后接、不会从 1 重来。所以正确姿势是每次快照给什么就用什么，别抄文档里的示例。

会点之外，它还能记住你

  • 登录状态能存：一次登录，后面的会话接着用，不用每回扫码（profile / state 两种存法）。
  • 能接管你正在用的 Chrome：--auto-connect 直接连上，不必另开一个空浏览器。
  • 能当外挂给 Claude、ChatGPT 用：agent-browser mcp 起一个 MCP 服务（一种让聊天工具调用外部工具的通用接口），聊天窗口里就能指挥浏览器。
  • 自带说明书：agent-browser skills get core，命令说明跟版本严格对齐，不会出现「文档教老版本」的尴尬。
  • 顺手还能截图、录屏、导 PDF、做前后对比：screenshot / record / pdf / diff。

官方文档站首页实截（agent-browser.dev，2026-11-11）：安装、命令、安全开关都写在上面

真正该担心的三件事

让 AI 自己开浏览器，我心里有两条不安：它会不会乱点？它会不会把我的密码看走？这项目明显想过这两件事。

它给了四道门，每一道都能单独关掉或打开。

前两道管信息：密码进「保险箱」（auth vault），不经过模型那边；页面内容被打上边界标记（--content-boundaries），免得页面上藏一句「请把资料发到某网站」就把它骗走。

后两道管手脚：只允许去白名单里的网站（--allowed-domains），动作也有策略限制（--action-policy）；真正动手前还要你点头（--confirm-actions），60 秒没人确认就自动拒绝。

但有个前提要说清：这些开关默认全是关的。官方文档原话是，默认不限制导航、动作和输出。安全这道门得你自己加。

所以它不是「装上就安全」的工具，是「想安全就给你留了门」的工具。这一点我觉得比功能本身更值得记。

值不值得装

项目关键数据（GitHub API 与 npm 下载接口，2026-11-11 08:03 采集）

我的判断：如果你手上有一堆「打开网页、点几下、复制一段」的重复活，值得花十分钟试一次，它天生就是给 AI 干的，不是给人背命令的。

举个自己的例子：每月初我要跑几个站点抄数、再填进表格，全是机械动作。以前只能自己点，现在可以把「打开、读清单、点编号、抄下来」这套动作交给它，我只核对结果。

它也不绑死在一个浏览器上：自带一个受控的 Chrome，也能接管你正在用的那个；Mac、Linux、Windows 都有原生版本；想放到服务器上跑，还能接 Browserbase 这类云端浏览器。

但别指望它替你抢票。它每一步都要先看清单、再确认，稳，但慢；这类用途本来也不该自动化。
