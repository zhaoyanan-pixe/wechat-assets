「视频号的定时可能被改，遇到过 +2 小时。」

这句话不是吐槽帖，是一个开源项目的说明书里写的。

它甚至为此专门做了一件事：提交完，回头去平台把定时读一遍，跟自己的计划表比对；对不上，就在飞书群里弹一张警告卡。

看到这儿我笑了一下。不是笑它较真，是笑这种憋屈太熟了：你这边排得好好的，平台那边悄悄挪了，等发现，时间已经过去了。

项目叫麦田，作者是 B 站、小红书上教 0 基础 AI 的博主「麦当」。11 月 14 日建仓，今天早上 2,280 星、595 个 fork。

说实话，2,280 星在今天的 GitHub 上不算爆款。但它干的事，比很多上万星的项目实在。

一句话：你对 AI 说「整理发布」，一期视频的七个平台文案它来写；剩下的排期、填写、取链接、采数据，它自己跑。

图注：官方大屏：最新一期、各平台数字、粉丝、转化（演示数据；来源：仓库 docs/screenshots/board.jpg）

三块拼起来的，缺一块都跑不动

第一块是给 AI 助手看的说明书。它让 Claude Code 或 Codex 先看片，写完 B站、抖音、小红书、视频号、YouTube、X、Instagram 七份不一样的文案，再生成一个发布工程文件。

第二块是一个 Chrome 插件。它自己打开七个平台的上传页，传视频、传封面、填文案、设定时。

第三块是麦田本身：负责排期、防重、等你点发布、到点取链接、每天采数据，再把结果推到你手机和飞书群。

图注：官方演示（26 秒）：AI 写文案 → 进分发计划 → 插件分批填写 → 国内平台由人点发布（来源：仓库 Releases 演示素材，已压缩体积）

最有意思的一条，是它不肯替你按

七个平台里，只有 X、YouTube、Instagram 和自有站点是「回读一遍、文案和定时都对，就自动提交」。

B站、抖音、小红书、视频号这四家，它填完就停。然后守护进程每 20 分钟提醒你一次：该你了。

README 把理由写得很直：自动化只负责填写和核对，最后一下人点，降低风控风险。

我觉得这不是技术做不到，是边界划得对。平台最忌「机器人批量发」，最不忌「人用工具省点力气」。填表是机械活，可以交出去；发不发、什么时候发，是判断，得留在人手里。

这个分法，比任何「全自动」的宣传都聪明。

图注：七个平台的分工：海外四家自动提交，国内四家填完等你按（依据 README 整理）

平台不讲道理的地方，它都写下来了

这一节我看得最久，因为全是踩出来的。

同一条视频，每个平台只上传一次。反复重传最容易触发风控，它做防重就是为这个。

成片必须 faststart（把索引放在文件头），不然小红书报「无视频流信息」，抖音连表单都不给你。

YouTube 的上传对话框被你关掉，视频可能已经排好定时了。所以它先去 Studio 列表里查一遍，再下结论。

小红书走的是最保守的路：只读页面上已经渲染的内容，像人一样滚动、点击，不在页面里直接调它的接口，频率压低。

连「专用 Chrome 卡死」都有解法：用 curl 关掉卡住的标签页，不会弹「离开此网站」的确认框。

还有一条，跟我们自己有关

仓库里有个 examples/wechat 目录，是公众号的接入示例。

它能把你写好的文章直接存进公众号草稿箱：标题、摘要、正文、封面自动转成 900×383 传图床，还会校验「标题 ≤64 字、摘要 ≤120 字、正文 ≤2 万字」。

但作者在上面压了一行警告：非官方支持，风险自负，默认不启用，只建草稿、不群发。

原因也写了：公众号这条不是「模拟人填表」，是直接在后台页面里调接口。

我的态度很明确：它能省掉复制粘贴的一大半，但踩的是「非真人自动化」那条线。账号是自己的，这条我先看着，不动。

它真正值钱的地方，是「每天自己回来」

每天上午采一次各期的播放和互动，新一期头三天每 6 小时一次；到第 1、3、7 天，自动出一张复盘卡，每周一出一张周报。手机上看大屏，群里看卡片。

图注：官方演示：分发计划日历，已发、已定时、等你点、计划中一眼分清（来源：仓库 docs/screenshots/calendar.jpg）

接上你自己的站点，还能看见哪一期、哪个平台真的带来了注册和钱。这一点比播放量诚实得多。

冷水

要一台常开的电脑。macOS 是官方支持，Windows 有社区贡献的安装脚本，但开机自启那段还没适配。

Node 22.5 以上、一个专用 Chrome、七个平台挨个登录一次。三级上手，官方的说法是：只看数据约 30 分钟，能分发再加 1 小时。

它才 13 天：7 位贡献者，7 个 issue、5 个 PR 还开着，没有正式版本号（唯一的 Release 是放演示素材的）。

数据这块倒很干净：只读你自己账号的创作者后台，配置文件、数据库、登录态都不进 git，工具本身不上报任何数据；作者知识站的链接带 utm 参数，不想看可以在配置里关掉。

图注：几个能对上的数字（GitHub API 实取，2026-11-27 09:55）

🧰 上手小抄
① 想看效果不用装：clone 下来跑 node src/demo.mjs，浏览器开 localhost:8788，假数据的大屏就出来了，不碰你的任何账号。
② 只想管数据：照 README 的 L1，约 30 分钟，把已发的期用 hub adopt 登记进去，第二天起每天有数字。
③ 一个小坑：成片一定要 faststart，不然小红书和抖音直接不认；专用 Chrome 卡了先关标签页，别急着重启。
