你有没有过这种时刻：让 AI 改个小功能，它两分钟就回「完成了」；你上手一跑，坏的。不是它没干活，是它从头到尾没搞懂你要什么。

刚过去的一周，GitHub 上有个项目冲到全站周榜第二：一周涨了 9,000 多星，总数 28.7 万。仓库今年 2 月建起，更新很勤，最近一次提交就在昨天。它想解决的，就是这种「错位」。

项目叫 mattpocock/skills，一句话介绍写着 Skills for Real Engineers，给「认真做工程」的人。作者 Matt Pocock 是英语圈很有名的 TypeScript 讲师，他的开发者通讯有约 6 万人订阅。

项目说明的开头，他补了半句很扎心的话：这些技能我每天在用，用来做「真正的工程」，不是 vibe coding（把需求丢给 AI、凭感觉写代码那种玩法）。

仓库主页实拍：Star 已在 28.7 万量级，About 里那句「Skills for Real Engineers」就是它的自我介绍（来源：github.com，2026-10-13 截图）

我把它的说明书翻了一遍，发现最值钱的地方不是功能，而是一个总结：AI 写代码翻车，来来回回就 4 种。每种翻车，他都配了一个能直接装上用的技能。

4 种翻车 × 4 个药方（自制卡；据项目 README 整理，2026-10-13）

翻车一：干的不是我想要的

这大概是所有人踩过的第一个坑：你说了、它做了、一看不对。作者的办法有点反直觉：动手之前，先让 AI 反过来拷问你。

他做了两个技能：/grill-me 和 /grill-with-docs。你抛出一个想法，它一个接一个问你细节：数据从哪来、谁有权限、出错怎么办……问到每个分支都定下来为止，才允许开工。作者说，这是他全部技能里最受欢迎的两个。

「先拷问、再动手」场景示意：AI 反问你，把含糊的地方一个个问清楚（自制卡，据官方描述绘制）

细想挺有道理：多数时候不是 AI 不懂你，是你自己也没想清楚。先被问上一轮，含糊的地方就藏不住了。

翻车二：20 个词能说的事，说了 20 句

第二种翻车是「话太多」：同一件事绕来绕去，你越听越糊涂。作者开的药方是一份共享词汇表（GLOSSARY.md）。

他举了自己项目的真实例子。改之前，一句话这么写：「课程里的一节课被『实体化』（也就是在文件系统里拿到自己的位置）时，有问题。」改之后只剩一句：「『实体化级联』出问题了。」

把行话固定下来、写成文件，AI 和人共用：说起来变短，但更准；代码里的命名跟着统一，AI 也少烧 token。作者说，这可能是整个仓库里最酷的一招。其实这不算新发明：它在 README 里标了出处，这种「通用语言」出自 Eric Evans 的《领域驱动设计》，他只是把它翻译成了 AI 能照做的版本。

翻车三：功能写完了，一跑就报错

第三种最气人：看着都写完了，一跑，报错。作者的说法是：没有反馈，AI 也不知道自己对不对，只能「盲飞」。

药方是给 AI 搭反馈回路：类型检查、能看浏览器、自动测试，其中最关键的是一套「红绿循环」：先让它写一个一定会失败的测试（看着它变红），再写代码让测试变绿。配套还有 /diagnosing-bugs：遇到难缠的 bug，先搭一个能稳定复现的环境，再一步步缩小范围，不许靠猜。

翻车四：代码越写越乱

最后一个，也最容易被忽略：AI 写得快，代码也乱得快。以前一个烂摊子要攒三年，现在可能三个月。作者把它叫「代码泥球」。

他的解法是把「关心设计」变成日常动作：有个技能叫 /improve-codebase-architecture，隔几天在项目里跑一圈，把「哪里该拆开、哪里该并起来」列成单子给你挑；扫完先给一份能点的 HTML 报告，你挑中哪条，它再陪你往下深挖。丑话说在前面：它是巡检，不是抢救，烂成泥山的代码它也不会替你拆。

装它，只要 30 秒

官方管安装叫「30 second setup」：Claude Code 一行命令、Codex 两行，Copilot、Gemini 也都有；不挑工具的话，用 npx skills 一键接进任意 AI 编程工具。全部是纯文本的 Markdown 文件，MIT 开源，免费。

官方文档页实拍：「AI Skills for Real Engineers」，安装命令就在页面上（来源：aihero.dev/skills，2026-10-13 截图）

还有个细节挺贴心：技能分两类。一类要你主动喊（像 /grill-me）；一类平时不吭声，AI 碰到合适场景自己就会用（像 /tdd）。挑花眼了也不怕：里面有个小帮手 /ask-matt，不知道该用哪个，直接问它。

作者写在说明书里的态度我很喜欢：别当圣经供着，欢迎拿去折腾、改成你自己的。（原话：Hack around with them. Make them your own.）

对了，翻贡献者名单时我乐了一下：上面除了作者，还躺着一位「Claude」。一个「AI 给 AI 立规矩、再请人来改」的仓库，这个套娃挺妙。

写这篇时我最大的感受是：27 个技能里，没有一条是「咒语」。全是老规矩：先想清楚、说人话、小步走、常回头看看。区别只是，以前这些是老师傅张嘴念叨的；现在写下来，AI 就真的能照做。

工具人人能装，技能人人能抄。但「先把要什么想明白」这件事，AI 替不了你。

🧰 上手小抄

③ 一句提醒：两个安装渠道别同时用（会重复装一份）；技能全是纯文本 Markdown，能改能删，欢迎改成自己的规矩。
